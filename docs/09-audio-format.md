# 09. 오디오 포맷 (VAG / VPK)

도구: `devple.gow.tools.audio` — `audio:wav <in> <out.wav>`, `audio:all <gow-rom> <outDir>`
결과: 616개 파일(VAG 390 + VPK 226 고유) 모두 WAV 변환 성공.

## 1. PS-ADPCM (공통 코덱)
16바이트 프레임 = 28샘플.
| 바이트 | 내용 |
|-------|------|
| 0 | 상위 4비트 predictor(0–4), 하위 4비트 shift |
| 1 | flags: 1 루프 끝, 2 루프, 4 루프 시작, 7 무음/종료 |
| 2–15 | 4비트 부호 있는 샘플 28개 (하위 니블 먼저) |

`sample = (nibble << 12 >> shift) + h1·c0 + h2·c1`, 계수 `{0,0} {60,0} {115,-52} {98,-55} {122,-60}` / 64

## 2. VAG — 효과음/짧은 음성 (모노)
빅엔디언 48바이트 헤더.
| 오프셋 | 타입 | 필드 |
|-------|------|------|
| 0x00 | char[4] | `VAGp` |
| 0x04 | u32 BE | 버전 (0x20) |
| 0x0C | u32 BE | 데이터 크기 |
| 0x10 | u32 BE | 샘플레이트 (22050) |
| 0x20 | char[16] | 이름 |
| 0x30 | – | ADPCM 데이터 |

## 3. VPK — 스트리밍 음악/음성/앰비언트 (멀티채널)
리틀엔디언.
| 오프셋 | 타입 | 필드 | 관찰값 |
|-------|------|------|--------|
| 0x00 | char[4] | `" KPV"` | |
| 0x04 | u32 | **채널당** 데이터 크기 | 190,384 × 2ch ≈ 파일크기 − 0x800 |
| 0x08 | u32 | 데이터 오프셋 | 0x800 |
| 0x0C | u32 | 블록 크기 (**모든 채널 합계**) | 항상 8192 |
| 0x10 | u32 | 샘플레이트 | 22050 / 32000 / 44100 |
| 0x14 | u32 | 채널 수 | 2 (일부 4) |

데이터는 채널별로 `블록크기 / 채널수` 바이트(2ch → 0x1000)씩 번갈아 배치된다.

### 인터리브 크기 결정 과정
0x0C(8192)를 채널당 크기로 해석해 디코딩하면 음성 파일(`A01HL17.VPK`)의 좌우 상관계수가 0.02로, 스테레오 음성이라고 보기 어려웠다.
인터리브 크기를 0x10~0x10000 범위에서 바꿔 가며 상관계수를 측정한 결과 **0x1000일 때만 0.67**(수정 후 전체 파일 기준 0.77)로 뚜렷했다 → 블록 크기 = 채널 합계.
앰비언트 루프(`UWATH4LP.VPK`)는 어떤 크기에서도 상관이 낮다. 좌우 독립 소스로 녹음된 것으로 판단한다.

## 4. 이름 규칙 (관찰)
- `A01HL17` 등 `HL` = 대사(hero line?) 계열 음성, `*LP` = 루프 앰비언트 (`UWATH4LP` 수중 아테네, `WETRM1LP`)
- WAD 내부 `SBK_*` 사운드뱅크와 `SND_*` 이름 리스트(PARAM 태그)가 레벨 효과음을 참조 — SBK(`SBlk`) 포맷은 미분석

## 5. 엔진 연동 계획
LWJGL OpenAL 로 재생. 짧은 VAG 는 메모리 버퍼, VPK 는 스트리밍 버퍼 큐(디코딩을 블록 단위로).
