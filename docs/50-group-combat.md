## 1. 동시 공격 제한 (재확인) [확실]
17 문서 §4 그대로 — 바꾼 것 없음. 대상 슬롯 (vtable+0x78): +0x0C 토큰 예산, +0x0E/+0x10 공격 슬롯 사용 A/B, +0x12/+0x14 용량 A/B, +0x16 플래그.
- 토큰 획득 0x1CDEC8: 거리 &lt; 대기 반경 (0x96) × 16 × 1.1, 자신 경직 (guard 2) 아님, **대상 무적 (0x2441E0 비트 2 = 이벤트 9) 아님**, 전역 정지 아님, 예산 + 비용 ≤ 용량 (0x200130).
- 반납: 거리 &gt; × 1.5, 자신 경직, 대상 무적, 전역 정지 → 칸도 해제 (AI+0x88 = 0xFF, 0x1CE1E0).
- 공격 0x1CC980: 비용 A ≤ 용량 A − 사용 A (토큰 없으면 0 → 비용 0 행동만 = 도발), 대상 슬롯 +0x16 & 3 (무적) 이면 용량 0.
- 크라토스 Sold_000: 비용 4, 용량 12, A 10, B 10 → 해골 (비용 4) 토큰 3, SKU3HIT (A 3) 동시 3, 미노타우로스 (비용 2) 토큰 6, AXEATTACK2 (A 5) 동시 2.
- **영웅 무적 기술 = 모든 적 토큰 반납** (데이터 R_PERMK INVULNERABLE): EVADE* [0–0.2], HITBALL·HITLIE·HITGETUPGROUND, 일어난 뒤 IDLECOMBAT 195 [0–1], 처형 MAI* 대부분.
  → 굴러 피하거나 넘어졌다 일어나는 동안 둘러싼 적이 모두 대기 반경으로 물러났다가 다시 토큰을 잡는다. 엔진은 이미 그대로 (`AiBrain.targetLocked`).

## 2. 갱신 순서 [확실]
AI_Update 0x1D0E08 (매 프레임): 기술 중이면 토큰만 (0x1CDEC8) — 단 기술 +0x12 & 8 이면 이동도 (해골 기술은 해당 없음). 아니면 0x1D2FB0 (공격 끝 → pause × 난이도) →
Mode 0/3/4 = AI_CombatMove 0x1CE2E0, 그 밖 = 0x1CC980 직접. 생각 주기는 매 프레임 (별도 간격 없음).
0x1CE2E0: 토큰 갱신 → 반경 = (토큰 ? 0x94 : 0x96) × 16 → 자신 상태로 분기
- 줄 (+0x174 & 0x400) 또는 벽 + 0x400000 → 0x1CDBF0 (격자 없음: 줄은 대상 쪽 내비 점으로 이동 + 매 프레임 0x1CC980)
- 그 밖: 대상 격자 상자 (격자 중심 ±176, 격자 축) 안이면 0x1CD788 (칸 판단) + 0x1CD300 (칸으로 이동), 밖이면 0x1CD2A0 (곧장 — AI+0x30 내비 경로 0x1D3F50).

## 3. 포위 격자 (대상 슬롯 +0x04) [확실]
생성 0x20AAC8 (전역 목록 0x29F310 에 등록), 갱신 0x20B038 — **대상 자신이** 매 프레임 (영웅 0x1D89F8, 적 0x1D0C08 은 템플릿 0x84 & 0x400 일 때),
공중 (+0x174 & 0x4C) 이면 갱신하지 않음.
```
+0x00/+0x10/+0x20 축 (지상 = 월드 축, 벽 = 대상 행렬), +0x30 중심, +0x40 점유 121 비트, +0x50 벽, +0x60 그림자, +0x70 시각
칸 c = i×11 + j, 중심 = +0x30 + X (i−5)×32 + Z (j−5)×32, 위치 → 칸 = trunc((p − (중심 − 176(X+Z)))·축 / 32) (0x20AF30)
```

### 3.1 격자 이동 0x20B038
- 재구성 (처음 / 대상 높이 32 넘게 바뀜 / 축 기울기 up·up' &lt; 0.9 / 시각 낡음): 축 = 대상 행렬, 중심 = trunc(p·축/32)×32 − 16 (X·Z), 높이 = 대상. 121 칸 벽 다시.
- 아니면: 대상이 가운데 칸 (±16) 안이면 그대로. 밖이면 대상이 든 칸 (i, j) 만큼 **중심 += ((i−5)·32, (j−5)·32)**, 남는 칸의 벽 비트는 옮기고 새 칸만 계산 (0x20B604).
- 끝으로 그림자 다시 (0x20C8E8), 점유 비우고 가운데 칸만 (0x20B838: +0x44 = 0x10000000 = 칸 60).
→ 중심 = 대상이 든 32 칸의 중심. **영웅이 칸 안에서 움직이는 동안 포위 칸은 월드에 고정**이고, 칸을 넘으면 32 씩 뛴다.
예전 엔진은 칸 중심 = 영웅 위치 + 오프셋이라 콤보 루트 모션·걷기마다 모든 적의 목표가 미끄러져 계속 발을 고쳐 디뎠다.

### 3.2 점유 = 몸 0x1E10E8 [확실]
공용 내비게이션 갱신 0x1EBD78 의 맨 앞 (0x1EBDE8) 이 **모든 생물** (영웅·적) 에 대해 활성 격자마다: 자기 칸 + 주변 5×5 중 칸 중심이 몸 반경 (vslot 0xC0 × 16) 안인 칸의 +0x40 을 세운다.
예약이 아니다 — 두 적이 같은 빈 칸을 고를 수 있고, 먼저 닿은 몸이 그 칸을 막으면 뒤 적의 A\* 가 실패해 다시 고른다.
엔진: `AiTargets.Slot.refresh` (기록 갱신 담당 AI 가 프레임마다 한 번, 몸 = `BodyPush` 몸 목록, 반경 = Sold 몸 상자 [추정: vslot 0xC0 = 몸 반경]).

### 3.3 칸 판단 0x1CD788
```
if 칸 == 0xFF: 칸 = 고르기(자기 칸, 반경); +0x7A = +0x76 = 0; 끝
멂 = 거리 > 0x78 × 16                                   (0x1D3CC0)
칸 안 = |d·X| ≤ 16, |d·Z| ≤ 16, (칸 중심 − 자기)·위 ≤ 0    (자기가 격자 높이 이상)
+0x7A += 16ms                                             (선택 후)
칸 안이면 +0x76 += 16ms
아니면 { if 토큰 && !멂 && +0x76 ≠ 0: 칸 = 자기 칸   // 칸에 있다가 밀려남
         else if 칸이 벽|그림자: 칸 = 자기 칸
         +0x76 = 0 }
시도 = +0x76 > 0x20 || +0x7A > 0x22 || 거리 ≤ 0x74 × 16;  아니면 끝
토큰 없음: 거리 ≥ 0.75 × 대기 반경이면 0x1CC980 (= 비용 0 도발); 끝     ← 타이머를 되돌리지 않음, 재배치 없음
토큰:     ok = 0x1CC980
          if !멂: 끝                                       ← 가까우면 칸·타이머 유지
          if ok: 칸 = 0xFF, 타이머 0  else if +0x7A ≥ 0x22: 다시 고름
```
- **토큰 없는 적은 이 함수에서 칸을 다시 고르지 않는다** — 템플릿 0x24 ("토큰 없을 때 재배치 시간", 해골 5000) 는 s4 에 읽히지만 토큰 보유 경로에서만 쓰인다.
  다시 고르는 때는 칸 해제 (토큰 반납)·경로 없음·자기 칸이 벽일 때뿐. 대기 반경 칸에 선 적은 2 초 뒤부터 도발 (해골 TAUNT02–04, pause 0) 을 끊김 없이 잇는다.
  예전 엔진은 "그대로면 같은 자리에서 도발만 반복해 멈춘다" 며 도발마다 선택 후 시간을 0 으로 [근사] 했는데, 원작이 바로 그 동작이다 (영웅이 다가오면 0.75 배 안이라 도발을 멈추고 칸으로 물러남, 영웅이 상자 밖으로 가면 따라옴).
- **가까운 토큰 보유자 (≤ 64) 는 공격해도 칸을 놓지 않는다** — 선택 후 시간이 이미 0x22 를 넘었으니 공격 후 대기 (pause × AI Recovery Time Mult) 가 끝나는 프레임에 다시 공격.
  예전 엔진은 성공할 때마다 칸을 놓고 새 칸 (게다가 정사각형 무작위) 으로 걸어가 다시 2 초를 기다렸다.
- 높이 조건: 영웅이 적보다 높은 데 서면 (예 갑판 단 위) 아무도 "칸 안" 이 되지 않아 시도는 선택 후 2 초 (0x22) 로만 선다 — 원작 규칙 그대로 [확실] (엔진은 1 단위 여유 [근사]).

### 3.4 칸 고르기 0x20BA60 → 0x20BFB0 [확실]
1. 제외 = 점유 | 벽 | 그림자, 자기 칸에서 4 방향 flood fill (j−1 방향은 j &lt; 2 면 없음 — 원작 비교 `slti 2`, 그대로) 로 못 가는 칸도 제외.
2. 최대 5 번: v = X(2r−1) + Z(2r−1) 를 **정규화** (0x20C0F8 `vrsqrt` + `vmulq`) × 반경 → 격자 중심 + v 의 칸이 제외가 아니면 채택. → 칸은 **반경 원 위**.
   (32 문서 예전 해석 "반경 정사각형 안 무작위" 는 vrsqrt 를 놓친 것.)
3. 실패하면 rand(121) 칸, 막혔으면 0x243B68 이 4 번 더 무작위 (점유·벽·그림자만 봄), 그래도 없으면 −1 (0xFF → 다음 프레임 다시).
→ 토큰 보유자는 격자 중심에서 64 (= 영웅에서 42–86), 대기 적은 160 (138–182) 원 위에 선다.

### 3.5 칸으로 이동 0x1CD300 / A\* 0x20C1B0 [확실]
- 칸 없음 → 0x1CD2A0 곧장. 자기 칸이 벽|그림자 → 칸 해제 + 곧장.
- 자기 칸 ≠ 목표 칸이면 A\* (열린 목록 0x304C10, 이웃 0x20AC78 = 4 방향, **점유·벽 칸은 못 감** (그림자는 감), 비용 32, 추정치 = 칸 중심 직선 거리) 의 첫 칸으로.
  첫 칸 = 자기 칸 (경로 없음 — 목표 칸에 다른 몸이 섰거나 막힘) 이면 다시 고른다.
- 다음 칸 중심이 AI+0x30 구 밖이고 자기가 그 칸에 없으면 서 있다 [미상: AI+0x30 (내비 경로 객체 +0xC 반경) 의 정체 — 엔진 생략].
→ 대기하러 가는 적이 영웅 칸 (가운데 = 늘 점유) 이나 다른 적의 몸을 가로지르지 않고 돌아간다.

### 3.6 벽·그림자 [확실: 원작 / 근사: 엔진]
- 벽 0x20B870: AI 내비 노드 목록 (0x337A60, 개수 0x29DC08) 중 칸 중심에 가장 가까운 노드 (0x1D3F50 → 0x187D30) 가 노드 반경 (×16) 의 정사각형·높이 64 안이면 걸을 수 있는 칸, 아니면 벽.
  **엔진 [근사]**: 그 노드 자료가 없어 칸 중심 아래 바닥 (격자 높이 +16 ~ −64) 이 없거나, 바닥 위 20 의 반경 8 구가 장애물에 걸리면 벽.
  모든 칸이 막혀 고를 칸이 없으면 근사가 틀렸다고 보고 그 적은 다음 성공까지 벽을 무시한다 [근사]. 벽에 붙은 적은 벽 판정을 쓰지 않는다 (그물·벽면 노드 유무 미상) [근사].
- 그림자 0x20C8E8: 벽 칸마다 가운데 줄·열이면 바깥쪽 나머지, 사분면이면 그 칸에서 격자 모서리까지 직사각형.
- 예전 엔진은 대상 눈높이 → 칸 중심 시선이 막히면 벽 (그림자 없음) 이었다 — 시선 판정이 아니라 내비 노드 유무다.

## 4. 자동 조준 0x2077A0 (영웅·적 공용) [확실: 흐름]
Combatant 갱신 0x205968 이 기술 중 (+0x4C) 매 프레임 0x205AC0 에서 부른다.
- 안 돎: +0x1AC & 1 (**FLAG_1 창, 이벤트 15**), 벽·줄 (+0x174 & 0x30 / 0x400), 기술 +0x0E & 0x20 이고 대상 (+0x80) = 잡은 상대 (+0x84).
- 원하는 방향 0x207618: 대상 (+0x80) 중심 (vslot 0xE8) − 자기, 대상이 없으면 스틱 (입력 +0x0, 크기 &gt; 0.8) 아니면 정면, 수평 정규화.
- 회전: slerp(t = Auto Aim Damping (0x29F2F4 = 0.1) × clamp(프레임 시간 × 60 × 속도 배율, 0, 1)) — 60 fps 에서 남은 각의 10 % / 프레임 [근사: 속도 배율 vslot 0xC8 / +0x16C = 1].
- **적의 +0x80 = 영웅** (AI_SetTarget 0x1D3414). 예: 해골 SKU3HIT FLAG_1 [0.60–1.00] → 두 번 베는 동안 영웅을 따라 돌고 마지막에 고정, 미노타우로스 AXECOMBO [0.72–1.00].
  예전 엔진은 적이 기술 중 전혀 돌지 않아 옆걸음 한 번이면 헛쳤다 → 이제 무리 속 공격이 원작처럼 따라 붙는다.
- 영웅도 같은 규칙 (대상 = §5). 엔진: 기술 시작 때 스틱 방향 즉시 회전 (예전 근사, 출처 미확인) 은 유지하고, 스틱 중립 때 가장 가까운 적으로 즉시 돌던 것은 이 조준으로 바꿈.

## 5. 영웅 대상 고르기 0x1D9CB0 [확실]
플레이어 갱신 0x1D8470 → (잡기 플래그 0x8 이 아니면) 매 프레임 → combatant +0x80.
1. 후보 = "Targeting Range" (R_PERMK 10, 0x30408C) × 16 = 160 구 질의 (0x11E8D0, 콜백 0x1D9B88: 죽음·표적 불가 0x1E1A50 제외), 위치 = 중심.
2. 스틱 크기 (+0xF0.w) ≤ 0.8 이고 이전 대상이 후보에 있으면 **유지**.
3. 아니면 s = 카메라 기준 스틱 벡터 (길이 = 크기, 입력 갱신 0x1DD5F0), d = 후보 − 영웅, c = s·수평(d) / |d| &gt; 0.5 인 후보 중 **|d| / c² 최소**.
   스틱 중립 + 이전 대상 없음 → 대상 없음.
→ 무리 속에서 스틱을 적 쪽으로 밀고 공격하면 그 적에게 붙고 (±60°), 콤보 중 스틱을 놓아도 대상이 유지된다.
예전 엔진은 스틱과 무관하게 가장 가까운 적만 조준했다. 엔진: `HeroTargeting`, `GameScene.selectHeroTarget` (봇·잡기 대상은 그대로 가장 가까운 적).

## 6. 붙잡은 채 맞을 때 (동기 끊김) 0x2050D8 [확실]
Combatant 갱신마다 (양쪽 각자): 지금 기술 +0x0E & 0x60 이 0 이면 (기술 없음 포함) +0x84 (동기 상대) = 0, 0x4000 지움.
& 0x60 이고 +0x1AC & 0x4004 이면 상대에게 **기술이 없을 때** 자기 기술 끝 (0x209918).
- 크레토스가 해골병을 붙잡은 MAISKB01 (223, 0x13A, 무적 아님 — 토큰 반납 안 함) 중 다른 해골병에게 맞으면 HITKNOCKDOWN 182 (0x180) → 영웅 쪽 연결 끊김.
  붙잡힌 해골병 (MAISKB01 0x140, 영웅 FLAG_4 가 세운 0x4000) 은 영웅이 기술 중인 동안 그대로, 영웅이 일어나 IDLECOMBAT 80 (반복) 에서 아무 입력 (ANY_INPUT → 기술 없음) 을 하면 풀린다.
- 예전 엔진 (`GrabSync`) 은 적 쪽 MAI* 애니만 보고 결합을 유지 → 장면이 영웅 갱신을 건너뛰어 **크레토스가 끝까지 굳고**, 해골병은 토큰을 쥔 채 MAISKB01 반복.
  ATHN01A 자동 플레이 150 초에서 두 판 모두 이 상태로 후반 50–100 초를 날렸다 (아래 §8).
