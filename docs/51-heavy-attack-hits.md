## 1. 공격 판정 = 접촉 루프 [확실]
접촉 루프 0x13B688 → 구 대 구 0x13C400 → 콜백 0x203150 이 두 개체의 모든 구 쌍마다 OnContact 0x203AF0 을 **양쪽 방향**으로 부른다
(t0 = 상대 구 재질의 PartType, 공격 레코드 +0x18 과 비교). 대상 (+0x80) 은 부위·창 비교와 무관하다 — 블레이드 구가 닿은 생물이면 모두 피격 후보.
블레이드 사슬 스윕 (0x1FAFC8 → 콜백 0x1FAF40) 도 같은 OnContact.

### 1.1 0x209AB0 (공격 레코드 찾기)
- 기록 수 +0x9F ≥ 0x20 → 0 (그 기술은 더 맞히지 못함). 기록은 (상대 핸들, 공격 레코드) 쌍 (0x209C50), 기술 시작 0x209C78 에서 지움.
- 부위 == t0, 진행률 ∈ [start, end], **공격 +0x1A & 1 이면 상대 == 공격자 +0x80** (0x209BB8), 같은 쌍 기록 없음.
- 플래그 0x1 공격 (영웅 데이터): GRAB 200/750/801 (부위 1·9), COMBO5A 22/720/800, BRUTAL1 47/716 (부위 9), PARRY02 59, BLOCKFORWARDFLIP 4 (부위 9),
  COMBO4B 88/701, WALLGRAB*, ROPEHOHGRAB, AIRTHROWMISS 203, #84EF57FD 845 — 잡기·처형·연출용 (대부분 피해 0).
- 예: BLOCK360 (L1+□, 블레이드 공격 10 개) 로 둘레 6 적 = 최대 60 쌍 → 32 쌍에서 멈춤 (시험: 8 · 8 · 8 · 1 · 3 · 4).

### 1.2 OnContact 공격자 쪽 (상대마다) [확실]
ApplyHit 0x2032C0 (피해·반응·넉백 0x204458) → 히트스톱 0x203688 (공격자·피격자) · 히트 카운터 0x1DB5B8 (피해 > 0, 플레이어) ·
MFX 0x2034CC (공격자 +0x80 이 피격자가 아니면 배율 0.125, 바닥 피 자국 없음 — 엔진 `MagicFx.hitBlood` 이미 그대로) →
**공격자 이벤트 17 (0x2043B4 → 0x2090B8: 상대 = 그 피격자의 자세 태그 +0x1B0 · 종류 · HP)**, 분기가 맞으면 그 자리에서 0x209400 + 0x205190 으로 새 기술 →
같은 프레임 나머지 접촉은 새 기술의 창으로 본다. 막힘이면 피격자 이벤트 16 · 공격자 이벤트 22 (상대 = 피격자).

### 1.3 엔진
- `GameScene`: `hero.combat.setBystanders(살아 있는 적, 조준 가중 > 0)` — 예전엔 적끼리 (같은 편 0x8) 만 휘말림 목록이 있었고 영웅은 비어 있었다.
  조준 가중 0 인 NPC (오라클 310 · 무덤지기 309) 는 뺀다 [근사: 원작은 편 비트 0x203B88 이하로 거름 — 미해독].
- `Combatant.attacks` → `hits(상대)` → `contact(a, 상대)`: 대상·휘말림 같은 경로. 순서는 대상 먼저, 이벤트 17 분기가 큐에 들어가면 그 프레임 나머지 접촉 중단 [근사: 원작 접촉 순서 = 충돌 세계 목록 순].
- `HIT_LOG_MAX = 32`, 플래그 0x1 검사 (손 기술 판정 · 사슬 스윕 둘 다).

## 3. △ 홀드 = 띄우기 (시작부터 홀드 분기) [확실]
데이터: COMBO6A 32 (△) `[0.00–0.30] TRIANGLE/hold-from-start → M0 COMBO7A @0.05` → M0 `[0–0.25] AUTO → 29 COMBO4D` (부위 11 피해 8, 자세 태그 4 → 미노타우로스 A104
HITLAUNCH) → COMBO4D `[0.30–0.60] △ 홀드 → 10 COMBOJUMP` (따라 뛰어오름). 같은 꼴: COMBO3E `[0.25–0.45] △ 홀드 → COMBO7A`, `[0–0.40] □ 홀드 → COMBO4C` (lv4),
COMBO3F `[0–0.10]/[0.40–0.80] △ 홀드 → COMBO7A`, BRUTAL1 `[0.40–0.60] △ 홀드 → COMBO7A`.
- Combat_Update 0x205968: 0x205B88–0x205BD0 에서 f20 = clamp((클립 시간 + 프레임 시간 × 속도) / 길이) = **이번 프레임 뒤 진행률** → 0x208A98 의 f12.
- 0x208A98: 창 판정은 지금 진행률. 입력 (0x207E40) · 조건 (0x208578) 중 하나라도 실패하면 홀드 마스크 +0x70 의 그 분기 비트를 지움 (0x208D28). 우선순위 AUTO 1 /
  홀드 2 (비트 남아 있을 때) / 버튼 3 / 0x1000 분기 4. 고른 분기: 즉시 (flags & 1) 면 0, 아니면 창 끝 → **창 끝 ≤ f20 이면 큐**, 아니면 AUTO · mode 3 은 다음에 다시 (0x208E80–0x208EA0).
- 큐 실행 0x205D10: 실행점 ≤ f20 이면 시작.
- 예전 엔진: 큐 판정을 지금 진행률로 해 "창 끝 > 지금" 이면 홀드 분기를 버림 → 창 끝과 정확히 같은 프레임만 → **△ 홀드가 그냥 △**. 홀드 조건도 "기술 시작 때 눌려 있음" 근사.
- 지금: `Combatant.poll(in, t, progressAfter(dt))`, 홀드 마스크 `holdMask` (기술 시작 때 −1, 실패 분기 비트 지움). 결과: 32 → 0 → 29 → 10, 미노타우로스 HITLAUNCH 최고 100.
- [근사] 큐 실행은 여전히 지금 진행률 ≥ 실행점 (원작보다 한 프레임 늦음), AUTO 비즉시 분기는 창 안에서 바로 큐 (예전 근사 그대로).

## 4. 띄우기·튕김 높이 [확실: 경로]
피격 반응 HITLAUNCH 104 · HITBOUNCE 103 (미노타우로스, stateMask 3) 은 자유 이동 기술: 0x1EBD78 → 0x1ECD60 (중력 없는 3D 루트 모션 0x1E5F90 → 0x1EA200,
바닥 질의 0x1E3298 — 발 아래 3.2 (변위 6.4 이상이면 6.4) 까지만, 맞으면 지상, 아니면 낙하 상태 0x8 → 분기 마스크 0x4). HITLAUNCH `[0.20–1]! AUTO → 105 HITLAND` 은
지상 (분기 플래그 0x2) 일 때만이라 루트 모션이 다시 내려와 바닥에 닿을 때 착지한다.
- 예전 엔진: 내비 끝의 `landAfterGuard` (난간에 막힌 뒤 계단 높이 14 안 바닥에 붙이는 근사, 29a9ac1 — ATHN01A) 가 자유 이동에도 걸려, 루트 모션으로 6.4 를 넘긴 틱마다

- 지금: 자유 이동 중엔 `landAfterGuard` 를 건너뜀 → HITLAUNCH 0.34 에 높이 100, 0.75 에 착지 → HITLAND (평평한 바닥 시험).

### 4.2 공중 충격의 위 성분 [확실]
밀어내기 0x203890 은 vec.y·Sy 도 속도 +0xF0 에 넣는다. 이동 0x1EB3D8 의 0x1EBA18–0x1EBA40: `+0xE0 += +0xF0` 다음 `vaddx.y vf3, vf0, vf1x` (vf1 = 0) 로
+0xF0.y = 0 → 수직 속도에 **한 번** 더해진다. 영웅 공중 충격 (공격 +0x06): COMBO3A–D (0, 1000–1200, 200), AIRH1 (0, 1000, 150), AIRH2/3 (0, 600, 100) = 띄워 둠,
AIRV1 (0, −500 / −2000, 0), COMBO6A (0, −1000, 0), COMBO3F/7A (0, −3000, …), BLOCKLAUNCHERB 끝 (0, −10000, 250) = 내리꽂음. ÷ 질량 100 × 16 → AIRH1 +160 /초.
- 엔진: `Combatant.push` 가 y 도 넣고 `takeLift()` 로 꺼냄, `EnemyNav.lift` 가 공중 (낙하, 자유 이동 아님, 날기 아님) 일 때 `vy` 에 더함. 그 밖엔 버림.
- [근사] 날기 적 · 영웅이 받는 공중 충격의 위 성분은 버림. 자유 이동 중 (+0xF0 를 위치에 더하지 않는 0x1ECD60 경로) 수평 밀어내기도 엔진은 더한다 — 0x1ECD9C 의 +0xE0 처리 [미확인].

## 7. 남은 것
1. 큐 실행 시점 (원작 = 다음 프레임 진행률 ≥ 실행점, 엔진 = 지금 진행률) — 모든 버퍼 연결이 한 프레임 늦다. 영향이 넓어 이번엔 홀드 분기의 큐 판정만 고쳤다.
2. 접촉 순서·한 접촉 = 공격 레코드 하나 (0x209AB0 은 첫 일치 레코드만) — 엔진은 상대마다 모든 창 공격을 같은 프레임에 본다. 경계 프레임 (예 BLOCKLAUNCHERB 0.18) 에서 두 번 맞을 수 있다.
3. 원작 구 대 구 접촉이 프레임 사이를 보간하는지 (0x13C400 앞 VU0) — 엔진은 선형 스윕 (34 §5).
4. 충격파 반경의 시간 변화 · 각도 (Angle / 종류 +0x58 분기 0x1910D4) · MFX 템플릿 (+0x2E) · 석화 경로, 적 충격파의 영웅 피격 반응.
5. NPC 편 거르기 (0x203B88 – 0x203CDC 의 +0xF4 비트) 미해독 → 조준 가중 0 인 개체는 휘말림에서 뺌.
6. 자유 이동 중 수평 밀어내기 (0x1ECD9C 의 +0xE0 저장 조건) 미확인.
