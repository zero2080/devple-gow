# 00. 프로젝트 개요

## 목표
- 개인 소장 PS2 디스크의 데이터·실행 코드를 분석해 게임의 구조(UI, 전투, 스킬/마법, 성장, 씬 이동, 이벤트 등)를 이해한다.
- 에뮬레이션 없이 macOS(Apple Silicon)에서 네이티브로 동작하는 **재구현(re-implementation)** 을 만든다.
- 모든 분석 결과와 구현 결정은 단계별로 `docs/`에 기록한다.

## 대상 디스크 식별 — 주의
사용자는 「갓 오브 워 2」 한글판으로 알고 있었으나 분석 결과 **「갓 오브 워」(1편) 한글판**으로 판단된다.

| 근거 | 내용 |
|------|------|
| 부트 실행 파일 | `SYSTEM.CNF`: `BOOT2 = cdrom0:\SCKA_300.02;1`, `VER = 1.01`, NTSC |
| 메모리카드 데이터 | `R_PERMK.WAD` 의 `MC_DATA` 태그: `BKSCKA-30002GodOfWar` |
| 레벨 이름 | `ATHN`(아테네), `PAND`(판도라 신전), `DEST`(사막), `HDES`(하데스), `ARENA`(신들의 도전) |
| 마법/무기 리소스 | `R_MEDHD`(메두사의 시선), `R_LGHTN`(포세이돈의 분노), `R_THBLT`(제우스의 분노), `R_RDEAD`(하데스의 군대), `R_BRSRK`(아르테미스의 검 — 코드명 BerserkBlade, 06 문서에서 정정) — 모두 1편 |
| 실행 파일 문자열 | `AresCamera1`, `SCR_AresSky`, `/Player/MedusaHead` (2편 고유 명칭 Colossus, Typhon 등 없음) |

분석 방법과 산출물 구조는 1편/2편 모두 동일 엔진 계열이라 그대로 유효하다.

## 접근 방식 비교와 선택

| 방식 | 설명 | 판단 |
|------|------|------|
| A. 에뮬레이션 | PCSX2 | 사용자 요구 아님 (제외) |
| B. 정적 리컴파일 | MIPS R5900 → C++ 변환 + GS/VU/IOP HLE | 원본 충실도 최고. 그러나 산출물의 대부분이 하드웨어 에뮬레이션 코드가 되어 "게임 개발 역량"과 거리가 멀다 |
| **C. 분석 후 재구현** | 데이터 포맷·게임 로직을 분석해 자체 엔진으로 재작성 | **선택.** 렌더링/애니메이션/전투/UI를 직접 설계·구현하므로 학습 효과가 가장 크다 |

## 기술 선택

| 영역 | 기술 | 이유 |
|------|------|------|
| 분석 도구 | **Java 21 + Gradle(Groovy)** | 사용자 주력 언어. 바이너리 파싱(ByteBuffer, FileChannel)에 충분 |
| 실행 파일 분석 | 자체 MIPS 디스어셈블러 / rizin / (선택) Ghidra | 심볼이 제거된 ELF. Ghidra 역시 Java 기반이라 스크립트를 Java로 작성 가능 |
| 런타임 엔진 | **Java 21 + LWJGL 3** (GLFW, OpenGL 4.1 core, OpenAL) | macOS 는 OpenGL 4.1 이 상한이지만 PS2 세대 그래픽에는 충분. 필요 시 Vulkan(MoltenVK) 경로로 교체 가능 |

### Java 로 효율이 나오지 않는 부분 (그리고 대응)
- **정적 리컴파일(B 방식)** 이었다면 JVM 은 부적합: 메서드당 64KB 바이트코드 제한, 128비트 EE 레지스터/SIMD 미지원, 부호 없는 정수 연산 비용, GC 로 인한 프레임 지터. → C 방식을 택했으므로 해당 없음.
- **VU 마이크로코드(.DVP.overlay)**: GPU 대신 VU1 이 정점 변환/스키닝을 수행한다. 이를 재현하지 않고 **데이터만 해석해 GPU 셰이더(GLSL)로 대체**한다.
- macOS 의 GLFW 창은 메인 스레드에서 생성해야 하므로 `-XstartOnFirstThread` JVM 옵션을 사용한다.
