# 12. 레벨 구성 포맷 (배치 / 충돌 / 볼륨 / 카메라)

도구: `devple.gow.tools.level` 패키지 / `level:*` 명령

```bash
./gradlew -q :tools:run --args="level:info  gow-rom/ATHN01A.WAD"   # 배치, 충돌 시트, 볼륨, 카메라 요약
./gradlew -q :tools:run --args="level:check gow-rom/ATHN01A.WAD"   # 배치한 모델 AABB 중심 vs 인스턴스 기록 중심 (규칙 검증)
./gradlew -q :tools:run --args="level:mats  gow-rom/PAND01A.WAD"   # 배치 모델별 머티리얼/블렌드/텍스처/평균 정점색
```

| 클래스 | 역할 |
|-------|------|
| `GoInstance` | `go*` 인스턴스 (0x20001) 파싱, 인스턴스 행렬 |
| `LevelLayout` | 오브젝트(0x40001 + 그룹 참조) / 인스턴스 목록, 배치(`Placement` = 인스턴스 + 오브젝트 + 관절 월드 행렬) |
| `PlacedMesh` | 배치된 MDL → 월드 좌표 `TriMesh` (관절별 변환, STROW 제거, 체인 복제) |
| `CollisionSheet` | 정적 충돌 메시 `SheetHdr` (`RIB_sheet`) |
| `BallHull` | 볼록 볼륨 (`CDV_ CMV_ ENV_ SEV_`): 구(ball) + 평면 hull |
| `DebugWire` | 볼륨 외곽선 `mCDbgHdr` (`CDZ_ CMZ_ ENZ_ SEZ_`) |
| `CameraDef` | 카메라 `CAM_` |
| `LevelData` | 위를 묶고 볼륨/카메라를 소유 오브젝트 관절에 배치, `activeCamera(p)` |

## 1. 배치 규칙 (확실)

```
GROUP{ RES obj (CXT 0x40001, 관절)  RES MDL_x  RES ANM_x  RES CDV_x  RES ESC_x  RES CAM_x  RES CMV_x ... (size 0 참조) }GROUP
GROUP{ RES goobj (CXT 0x20001, 0x5C 바이트) }GROUP
```
- 레벨 지오메트리도 캐릭터와 같은 **오브젝트(0x40001) + 인스턴스(0x20001)** 구조다. 레벨 전용 포맷은 없다.
  오브젝트 = 관절 계층(05 문서) + 같은 그룹의 참조 리소스(MDL/ANM/COL/SCR/CAM/EMT/FX). 인스턴스 = 오브젝트 하나를 월드에 놓는다.
- 0x20001 레이아웃 (실행 파일 GO Load `0x133ED0`, InstanceToWorld `0x130D28` 로 확인):

| 오프셋 | 타입 | 필드 |
|-------|------|------|
| 0x00 | u32 | magic 0x00020001 |
| 0x04 | char[24] | 오브젝트(템플릿) 이름 — 레지스트리 조회 `0x17A7B8` |
| 0x1C | u16 | id (WAD 안 번호) |
| 0x1E | u16 | flags (대부분 1; 0/5 의미 미상) |
| 0x20 | vec3 (+w=1) | 위치 |
| 0x30 | f32 ×3 | 오일러 X, Y, Z (라디안). `MatrixFromEuler 0x184A98` = RotX→RotY→RotZ, 행벡터 `Rx·Ry·Rz` (`Mat4.fromEuler` 와 동일) |
| 0x3C | f32 | **균일 스케일** (트리거 존 66.9 등 = 단위 볼륨 확대, 0 = 사용 안 함) |
| 0x40 | vec3 | 월드 경계 중심 (툴 계산값, 배치 경로에서는 읽지 않음 → 검증에 사용) |
| 0x50 | f32 | 시작 애니메이션 시간 |
| 0x54 | u16 | 시작 애니메이션 번호 (0x58 s32 -1 은 미상) |

- **인스턴스 행렬** `G = Scale(s) · Rx · Ry · Rz · Translate(pos)` (행벡터).
- **관절 월드** `W[j] = L[j] · W[parent] … · G`, `L` = CXT 바인드 로컬 행렬. 정점은 관절 로컬(파트 규칙은 05 문서 §1.5) → `v · W[j]`.
- 예: ARENA06 `arena` 관절 0 = 스케일 0.5 + 이동 (800,0,0), `goarena` 위치 (-800,0,0) → 상쇄되어 원점의 0.5배 모델.
- **정적 메시(type 0x1D)의 STROW 는 버린다.** 정적 메시 위치에는 `STMOD 1 + STROW (ox,0,oz)` 가 더해져 있는데
  `STROW/16 · 관절 스케일 = 관절 이동 + 인스턴스 위치` (예 beams1: STROW (196608,0,200704) /16 ×0.125 = (1536,0,1568) = (-3424+4960, 0, 1040+528)).
  즉 툴이 월드 좌표를 int16 범위 밖으로 표현하려고 넣은 값이고, 게임은 관절 월드 행렬로 같은 위치를 만든다.
  STROW 를 빼지 않으면 ATHN01A 배 조각들이 2배 거리로 흩어진다 (08 문서 §4 의 "배치 없이 그리면 깨짐"의 한 원인).
- **검증**: `level:check` — 배치 후 모델 AABB 중심 vs 인스턴스 0x40 기록 중심.
  ARENA06 13개 중 12개 오차 0.0 (나머지 = 하늘 구), ATHN01A 29개 중 18개 ≤ 1.0, 나머지 ≤ 8 (구 중심 ≠ AABB 중심인 비대칭 메시), wake 50 (이동 애니메이션 물체).
- 하늘: ATHN01A `nightsky`(관절 스케일 2, 반지름 1024, 원점), ARENA06 `group2`(반지름 950, 08 문서의 "하늘 구체") 는 원점 중심 큰 구다.
  레벨은 원점에서 멀리 있으므로(ATHN01A 배 ≈ (1536, 0, 1800)) 게임은 `SCR_Sky` 로 카메라를 따라가게 그린다고 판단 [추정].
- 08 문서 §4 의 "거대한 검은 박스" = 배치 없이 겹친 지오메트리 + 하늘 구 안쪽. 배치하면 사라진다.

### 1.1 LOD / 가시성
- 메시 그룹(LOD)은 04 문서 규칙 그대로 (`lodDistance`). 레벨 뷰어는 LOD 0.
- 인스턴스 flags / 스케일 0 / 스크립트(ESC)가 숨기는 물체의 규칙은 미해석. 스케일 0 인스턴스(예 `pCube3585`)는 그리지 않는다.
- `chainCount > 1` 메시는 체인마다 다른 베이크 정점색을 갖는다. 체인 c 의 색 REF 를 쓰도록 수정 (16 문서 §3.5). PAND01A 어두운 방은 베이크 색 자체가 어둡다.
- 하늘 오브젝트는 SCR_Sky 가 **관절 0 위치를 카메라로** 옮긴다 (16 문서 §1.4). ATHN01A 바다는 하늘 미니어처의 일부.

## 2. 충돌 리소스 COL (서버 0x11, 매직 0x00000011)

이름 접두사는 실행 파일에 없다 — 형식은 데이터 시그니처로 갈린다 (Collision Load `0x11D2B8`).

| 시그니처 | 위치 | 리소스 |
|---------|------|--------|
| data+4 `"SheetHdr"` | 레벨 정적 충돌 메시 | `RIB_sheet` (레벨당 1개) |
| data+8 `"BallHull"` | 볼록 볼륨 (kind = data+4) | `CDV_` 0 동적 충돌, `CMV_` 1 카메라, `ENV_` 2 환경 트리거, `SEV_` 3 사운드 영역 |
| data+4 `"mCDbgHdr"` | 디버그 외곽선 | `CDZ_ CMZ_ ENZ_ SEZ_` (짝 볼륨의 와이어) |

### 2.1 SheetHdr — 정적 지형 (확실: 실행 파일 메시 생성자 `0x16B2D0` 의 오프셋 표와 일치)
정점은 **월드 좌표** (인스턴스 없음). ATHN01A AABB (1416,-176,1552)..(1648,176,1996) = 배 갑판.

| 오프셋 | 타입 | 필드 |
|-------|------|------|
| 0x04 | char[8] | "SheetHdr" |
| 0x0C | u32 | 크기 |
| 0x18 / 0x28 | vec4 | AABB min / max |
| 0x3C | u16 | kd 트리 레코드 수 |
| 0x3E | u16 | 리프 수 |
| 0x40 | u32 | 면 참조 수 |
| 0x46 / 0x48 | u16 | 삼각형 수 / 사각형 수 |
| 0x4A | u16 | 정점 수 |
| 0x50 | u16 | 표면(머티리얼) 레코드 수 |
| 0x64 | u32[11] | 섹션 오프셋: [0] kd 트리 8B, [1..3] 표면 레코드, [4] 비트필드 스키마, [5] 면 참조 u16, [6] 삼각형 10B, [7] 사각형 12B, [8] 정점 vec3, [9] 끝 |

- kd 트리 레코드 8B: 노드 = `u32` bit0=0, bit1-2 = 축(x/y/z), `u16 +2` 먼 자식, `f32 +4` 분할값 (가까운 자식 = 다음 레코드). 리프 = `u32 (start<<1|1), u32 count`.
- 면 참조 u16: bit0 = 사각형, 번호 = v>>1.
- 삼각형 10B `u16 0, u16 surface(&0xFFF), u16 v[3]` / 사각형 12B `u16 0, u16 surface, u16 v[4]`.
- 표면 레코드 / 스키마: `"Arena06Visuals_Death"`, `"ArenaRails_groundRock"` 같은 Maya 머티리얼 이름과 `bitfield0..3` 아래
  `Ground, Water, Narrow, Climbable, Ladder, Slide, Death, DeathVolume, doubleSided` 등 속성 이름이 있다.
  surface 번호 → 속성 비트의 정확한 대응은 미해석 [다음 단계]. 현재 엔진은 법선 Y 로 바닥/벽만 구분한다.
- 게임 질의: 선분 캐스트 `0x16BF98` (kd 트리 + 128칸 리프 캐시), 그 외 vtable 슬롯 6/7/0xD (구 질의 추정, 미분석).

### 2.2 BallHull — 볼륨 (소유 오브젝트 관절 로컬 좌표)
| 오프셋 | 타입 | 필드 |
|-------|------|------|
| 0x04 | u32 | kind (0 CDV, 1 CMV, 2 ENV, 3 SEV) |
| 0x08 | char[8] | "BallHull" |
| 0x14 / 0x18 | u32 | ball 수 / hull 수 |
| 0x1C | vec4 | 경계 구 (x, y, z, r) |
| 0x34 / 0x38 | u32 | 이름 수 / 평면 수 |
| 0x3C | u32[11] | 오프셋: [0] 이름 char[24][], [4] ball vec4 (x,y,z,r), [5] hull 별 평면 수 u8, [8] hull 중심 vec4, [9] 평면별 이름 번호 u8, [10] 평면 vec4 (n, d) |

- 내부 판정: ball 안이거나 hull 의 모든 평면에서 `n·p + d <= 0`. 평면 n 은 관절 스케일이 반영된 비정규 벡터(0.25, 0.5)다 — 로컬 좌표에서 부호만 본다.
- 이름표: CMV 는 `RCM_<카메라>` (카메라 게임 오브젝트 레지스트리 이름, 실행 파일 `0x13EA98`), SEV 는 `RSE_<이미터>`, CDV/ENV 는 Maya 머티리얼 이름.
- **CMV → 카메라 선택**: hull 의 첫 평면의 이름 번호 = 활성화할 카메라. ATHN01A `CMV_Boat1Cams`: hull 6개, 카메라 5개, 번호 `0,1,2,0,3,4`.
  플레이어 위치를 포함하는 hull → `RCM_` 이름 → 카메라 [데이터상 확실, 실행 파일의 선택 루프는 미확인].
- CDV: 깨지는 항아리 = ball 1개 (r 16), 함정문 = 6평면 상자. ENV: 사망 존, 체크포인트, 순찰 변경, 로드 체크 등 (ESC 스크립트와 같은 오브젝트 그룹).

### 2.3 mCDbgHdr — 볼륨 외곽선
`0x10 u32[4]` = (hull 별 정점 수 u16[] 위치, hull 별 인덱스 수 u16[] 위치, 정점 vec4 위치, 선분 u16 위치). hull 마다 정점 n 개, 선분 인덱스는 hull 안 번호. 정점 수 0 = 끝.

## 3. 카메라 CAM_ (서버 0x09, 0x24C 바이트, 소유 오브젝트 관절 로컬)

| 오프셋 | 타입 | 필드 |
|-------|------|------|
| 0x08 | u16, u16 | (0, 0xFFFF), IdleCam 류 (1, 0xFFFF) |
| 0x10 | vec4[3] | 회전 행 (관절 스케일의 역수만큼 커져 있어 관절 월드를 곱하면 정규직교) |
| 0x40 | vec4 | 위치. 카메라는 로컬 **-Z** 를 본다 |
| 0x50 | char[32] | 레일 커브 이름 `NCV_x` (MESH_EXTRA 0x70 태그, 첫 바이트 0 = 없음) |
| 0x70 | f32 ×23 | 파라미터 블록 (실행 파일이 obj+0x10 으로 복사). 0x70 = 0.95 (기본값, FOV 라디안 후보), 0x78 u16×2 모드 |
| 0x80..0xA4 | f32 쌍 | 로더가 min ≤ max 로 강제하는 4쌍 (0x80/84, 0x88/8C, 0x98/9C, 0xA0/A4): 추적 거리/높이 범위 추정 |
| 0x90 | f32 ×2 | (90, 85), (30, 30), (7, 0) … 각도 계열 |
| 0xCC | char[32] ×12 | 참조 이름 (추적 대상/스플라인 추정, 실행 파일 확인) |

- 카메라 월드 = `local · W[관절]`. 오브젝트에 카메라와 같은 이름의 관절이 있으면 그 관절(ANM 으로 움직이는 IdleCam 등), 없으면 관절 0.
- 검증: ARENA06 `CAM_camera1` → 눈 (3, 102, 392), 원점(아레나) 방향 아래 17° — 실제 아레나 전경. ATHN01A Boat1Cam1~5 는 갑판 둘레.
- 게임은 이름으로 카메라를 바꾼다: `"RCM_" + 이름` (`0x1EDF48`, 없으면 `default`). 레일(NCV) 위 이동, 대상 추적, FOV 의 정확한 계산은 미해석.

## 5. 신뢰도 / 미해결
- 확실: 인스턴스 레이아웃·행렬(실행 파일 + `level:check` 일치), 관절 결합, STROW 제거, Sheet 면/정점/kd 레이아웃, BallHull 평면·ball, CMV 이름표.
- 추정: 하늘 돔이 카메라를 따라감, CAM 파라미터 의미, 0x1E flags.
- 미해결: 표면 번호 → `Ground/Water/Climbable/Ladder/Death` 비트, kd 트리 노드 상위 비트, 레일(NCV_) 포맷과 카메라 이동 규칙,
  실행 파일의 CMV 선택 루프(후보 `0x1EF620`, `0x1EE8E0`, `0x1EEFA0`), 체인별 정점색 선택, 스크립트가 숨기는/보이는 물체.
- PAND01A 일부 방(정점색 평균 ≈ 6/255)이 거의 검게 보인다 — 베이크 색이 실제로 어둡거나 다른 체인/동적 조명 몫. MAT 레이어 대부분이 `blend` 로 읽혀 반투명 패스로 그려지는 것도 확인 필요 (03 문서 영역).
