## 1. LGT_ 리소스 (LightServer 타입 6, 매직 6, 0x58 바이트) [확실: 디스어셈블]
- 서버: `Servers_Create` 0x17D420 "LightServer" (타입 6), 객체 0x241A30 → 0x151DA8 (vtable 0x2BD3F8, 전역 0x29CD44, 레지스트리 "Lights" 0xC8 칸).
  WAD 묶음 객체 vtable 0x2BD4D8 (0x241828, 0xF0 바이트 풀 0x20 개): 태그 처리 0x151C88 (데이터 → 0x3350F8 복사) → 0x151CD0 → vt+0x9C 0x2417C0 → 생성자 **0x1514C0**.
- 생성자 필드 대응 (16 문서 §3.6 의 [추정] 을 대체):

| 파일 | 런타임 | 의미 |
|---|---|---|
| 0x08 u32 | +0xC0 | 종류 비트: 1 = 점 (방향 = normalize(라이트 − 물체)), 2 = 방향 있음 (0x151978 정규화), 4 = 그림자 방향 합에 넣음, 8 = 전역 목록. 0 / 8 = 주변광 |
| 0x0C vec4 | +0x10 | 위치 (w = 1) |
| 0x1C vec4 | +0x20 | 방향 (물체 → 라이트, 위 = +y) |
| 0x2C vec3 + 0x38 | +0x30 | 색 rgb, w = 중심 세기 I0 |
| 0x3C | +0xC4 | 안쪽 반경 r0 |
| 0x40 | +0xC8 | r0 에서의 세기 I1 |
| 0x44 | +0xCC | 범위 r1 |
| 0x48 | +0xD0 (short) | 슬롯: 0 = 슬롯 0, 그 밖 = 슬롯 1 |
| 0x4C, 0x50 | +0xD4.. | 원뿔 (0x151978, 종류 비트 1·2) — 모으기는 쓰지 않음 |
| 0x54 | +0xE4 | 탈색 (물체 플래그 8 일 때만, 디스크 전부 0) |

- 디스크 통계 (214 WAD, 3455 개): (종류, 슬롯) = (2,1) 1134, (6,0) 1068, (1,1) 403, (6,1) 402, (0,0) 204, (2,0) 147, (1,0) 69, (5,·) 27, (14,0) 1.

## 2. 물체별 라이트 고르기 · 합치기 — 0x1521B0 [확실: 디스어셈블]
- 호출: 정적 모델 0x141EEC (모델 +0xC0 & **0x800** → 구 = (오브젝트 위치, 1)), 관절 모델 0x15986C (& 0x810, 결과는 0x800 일 때만 씀;
  구 = 모델 컴포넌트 LOD 바운딩 구 (+0x124 + 0x14·LOD: 반경 +4, 중심 +8) × 물체 행렬, 0x157E90). 모델 +0xC0 = **MDL +0x28 렌더 플래그** (04 문서).
  플래그 0x800 (디스크 228 개): MDL_hero 0x1800, MDL_MAIBlade / MAIgodblade, MDL_berserkBlade, 적·보스 (aoBHB, aoRED …), 정적 27 개 (MDL_DeadHydra* …).
  나머지 모델 (레벨, 상자, 줄 …) 은 라이트 묶음이 없다 → 조명 커널을 타지 않는다.
- 목록 (0x152150 → 0x152098, 라이트 추가·제거 때 더티 +0x40): 종류 비트 8 → 전역 배열 (+0x44, 수 +0x74), 나머지 → 공간 색인 (구 = 위치, r1).
  질의 = 공간 색인 0x1755B0 (최대 0x20) + 전역 배열 중 |P − C|² ≤ (R + r1)². R 은 1000 으로 자름.
- 세기: d = |P − C| − R/3. d &gt; r1 → 0, d ≤ r0 → (1 − d/r0)·I0 + (d/r0)·I1, 그 밖 → I1·(1 − (d − r0)/(r1 − r0)). × +0xE0.
  (탈색: 물체 플래그 8 이고 +0xE4 &gt; 0 이면 색을 최대 채널 쪽으로 +0xE4 만큼.)
- 합치기:
  - 주변광 (종류 0 / 8): 색·세기 합 ÷ 주변광 수 (평균) → qw 75.
  - 그 밖 (|f| &gt; 1e-5): 방향 = 비트 1 이면 normalize(P − C), 아니면 +0x20. **슬롯 (+0xD0) 별로 색·세기는 채널별 최댓값, 방향·세기는 합** → 정규화.
    슬롯 0 → qw 70–72 x 열 · qw 73, 슬롯 1 → y 열 · qw 74 (색 w = max(r,g,b)). 비트 4 라이트의 방향·세기 합은 그림자 방향 (a1 출력, 관절 모델 +0x100).
  - 방향은 카메라 행렬 (+0xB0) 회전으로 옮겨 넣는다 — 내적만 쓰므로 엔진은 월드 그대로.
  - 즉 **물체 하나는 방향 라이트 2 개 + 주변광 1 개** 로 비춰진다. "가장 가까운 N 개" 가 아니라 범위 안 전부를 슬롯별로 합친다.
- 0x70 바이트 블록 (0x3328C8 스크래치), +0x60 = 8 = VU 프로그램 조명 비트 (0x1682A8: 프로그램 플래그에 OR) → 0x13F928(블록, 6 qw, ·, VU 0x46).
  머티리얼 쪽 3 qw (0x13F928(·, 3, ·, 0x4C)) = qw 76 머티리얼 색, 77 더할 색, 78 알파.

## 3. VU1 조명 커널 [확실: 마이크로코드 `exe:vu1 … 0x2abb00` / `0x2ae000`]
- 주 프로그램 0x09F–0x0E8: vf27 = qw73 × M, vf28 = qw74 × M, vf29 = qw77 + qw75 × M (M = qw76 × 128, 머티리얼 색 비트가 없으면 128),
  vf16–18 = qw70–72 (xy 만) 를 모델 행렬 (vf20–22, 1/|행| 로 배율 제거) 로 옮긴 방향 행렬, vf29 += 2²³ (편향 정수).
- 커널 (라이브러리 0x0B5…): 법선 (itof15) → d = max(Lᵀ n, 0) (4 성분, zw 는 특수 경로 [미해석]) →
  **색 = vf29 + vf27·d.x + vf28·d.y**, `minii` 2²³ + 255 로 자름 → 정점 색 (메시 정점 색은 읽지 않는다). GS MODULATE 로 텍스처 × 색/128.
- 따라서 화면 배율 = M·min(주변 + 색0·max(n·L0,0) + 색1·max(n·L1,0), 255/128).
- vi10 비트 15 경로 (0x0A8–0x0B6: zw 에 추가 항, vf9 = qw78.x) 는 [미해석] — 엔진 미구현.

## 7. 캐릭터 그림자 — renShadowServer (타입 0x27) · SHG_ · MAT_stencil [확실: 디스어셈블]

### 7.1 구조
- 서버: `Servers_Create` 0x17D5DC "renShadowServer" (Server_Declare5, 타입 0x27, 렌더 순서 0x27 → 0x135FC0), 생성자 0x165580 (vtable 0x2BCB78) 이
  전역 0x3362D0 = **16** (밀어내기 기준), 0x3362D4 = 30 (가까운 감쇠 거리) 을 둔다.
- 리소스 **SHG_** (매직 0x27, "ShdowHdr07", 디스크 139 개: SHG_hero (R_HERO*), SHG_MAIBlade / MAIgodblade / berserkBlade, 적 aoBHB·SKS·HA2 …) —

  레벨 GO 를 위한 `SHGX_<레벨>` 은 서버 선언뿐이다. 포맷은 `ShadowGeometry` 주석:
  조각 = 관절 하나 (+0x11) 에 붙은 **닫힌 껍질** (정점 vec4, 면 법선, 모서리 v0/v1, 면 꼭짓점 (띠 순서), 면 모서리 참조 (모서리, 방향), 면 (개수, 시작)).
  SHG_hero = 19 조각. 면 고리 (모서리 참조) = 법선 기준 반시계, 모서리마다 방향 0 과 1 이 한 번씩 (전 디스크 1359 조각 중 열린 조각 8, 반대 고리 24/13864 면).
- 생성자 0x162338: 띠 수 = 3·Σ면꼭짓점 / 0xF4 + 1 로 **MAT_stencil** EE 프림 (0x162140: 타입 0x1C, PRIM 0x44 = 삼각형 띠 + 알파 블렌드) 을 만들고
  +0x140 = 16, +0x148 = 2, +0x14C = 0 (모드), +0xE0 = (0, 1, 0, 0) (받는 평면), +0x150 = 2.4, +0x154 = 1.6.
- **MAT_stencil** = `Servers_Create` 0x17D7C0 이 합성하는 머티리얼 "stencil": 헤더 색 (0.4, 0.4, 0.4), 레이어 GS ALPHA 0x44 (Cs−Cd)·As+Cd, 텍스처 없음,
  flags2 0x10000000, rgba (2, 2, 2, 1). 블레이드 사슬 그림자 (Blades_Init 0x1FA408, Shadow Diameter 0.13) 도 같은 머티리얼.

### 7.2 갱신 0x1628E0 (그림자 서버 갱신 0x162F20 → 오브젝트마다)
- 모델 = SHG 첫 조각 +0x10 번째 모델 컴포넌트. 모델 렌더 플래그 **|= 0x10** → 라이트 모으기 (0x15986C 의 & 0x810) 가 0x800 이 없어도 그림자 방향을 낸다.
- 구 = 모델 LOD 바운딩 구 × 관절 (+0x34), 반경 × 행 크기. **방향 = 모델 +0x100** (0x1521B0 의 비트 4 라이트 방향·세기 합, 정규화 0x1526FC — 물체 → 라이트 쪽).
  GO 부모 사슬 (+0x18) 에 렌더 플래그 0x810 모델이 있으면 그 +0x100 을 쓴다 (블레이드 → 영웅).
- **L = 중심 + 방향 × 64·반경** (+0x100), 방향이 0 이면 +0x130 = 0 → 그리지 않음 (비트 4 라이트가 범위에 없으면 그림자 없음).
- 모드 0: 밀어내기 배율 +0x12C = 16·min(16, +0x140) / (64·반경) → 정점 v 의 먼 점 v + (v − L)·f (≈ 256 유닛 = 16 m).
  모드 1: 0x162660 (점 L 에서 구를 받는 평면에 비춘 원뿔의 발자국 구) 이 0 이면 +0x148 bit 0 을 끈다. 모드 2: 같은 식을 평면 −1.6 에.
- 카메라 거리 감쇠 (모드 ≠ 1): 목록 0x2CD3F8 (+0x360 → 행렬 위치) 와의 거리 d (×1/16) 가 s = 1000 (+0x148 bit 1 이면 30, 0x1624E8) 을 넘으면
  배율 (1.1·s − d)/(0.1·s) 을 +0x12C 에 곱하고 0 이하면 끈다 [확실: 식 / 추정: 0x2CD3F8 = 카메라].

### 7.3 볼륨 0x162FB8 (렌더) — `ShadowVolume.build`
- 조각마다 관절 행렬 (가시성 비트 +0x64 가 꺼진 관절은 건너뜀) × 16 으로 정점·면 법선을 스크래치 (0x70000000) 에 옮긴다.
- 면마다 첫 꼭짓점 v0: **(v0 − L)·n < 0 (L 을 봄)** 이면 그 면의 모서리 참조마다 모서리 수 +1, 방향 기록. 아니면 **덮개** — 면 꼭짓점 띠를 가까운 점·먼 점 두 벌로.
- 수가 **1** 인 모서리 = 실루엣 → (v0, v1, v0', v1') 사각형 (GS ADC 0x8000 / 방향 비트로 감김 지정).
- 모드 (+0x14C):

| 모드 | 누가 | 가까운 점 | 먼 점 |
|---|---|---|---|
| 0 | 기본 (내비게이션 갱신이 없는 GO) | v | v + (v − L)·f |
| 1 | AI 생물 (0x1EBD78 → 0x1BF680, +0x174 bit 31 없음) | p + n·2.4 | p − n·1.6 (p = L 에서 받는 평면에 투영, 0x1640C0: t = (n·v + d)/(n·v − n·L)) |
| 2 | 영웅 (+0x174 bit 31 = 플레이어) | v | 평면을 1.6 내려 투영 (0x162510: d + 1.6) |

  → 모드 1 은 받는 면 위아래 4 유닛 판 (몸에는 그림자가 지지 않는다), 모드 2 는 몸에서 받는 면까지 (몸 아래쪽도 어두워진다).

### 7.4 받는 면 — 0x1BF680 (생물 내비게이션 0x1EBD78 끝, SCR_Shadow 0x2465B0 도)
- 반직선: 영웅 위치 + 위 × (크기·0.5·16) 에서 **normalize(위치 − L)** (빛 반대) 로 **128 × 감쇠** 유닛, 충돌 질의 0x11E190 (마스크 0xD330042),
  필터 0x1BF658 = 표면 bitfield1 **NoShadows (0x100)** 면은 건너뜀 (12 문서). 맞으면 평면 = (맞은 면 법선, −n·점), +0x148 bit 0 켬.
- 못 맞으면 영웅이 지상 (+0x174 & 3) 이면 영웅 바닥 법선 (+0x210) 평면, 아니면 bit 0 끔 → 모드 1 은 그리지 않는다 (0x163250).
- 모드 = 1, 영웅 (+0x174 bit 31) 이면 2. 같은 평면·모드를 **블레이드 2 개 (+0x338, 0x1FDC80 → 블레이드 +0xA8 bit 1, +0x60 평면, +0x70 L)** 와
  자식 GO 의 그림자 오브젝트 (0x1BF994) 에도 넣는다.
- 블레이드 사슬 그림자 (0x1FD218): 블레이드 +0xA8 bit 1 이면 사슬 점을 L 에서 평면에 투영한 띠를 MAT_stencil 로.
- **합성 [미해석]**: GS 에는 스텐실이 없다. 볼륨 띠는 MAT_stencil (색 0.4, 알파 블렌드) 프림으로 가고, 정점 w 의 방향 비트로 앞뒤를 구분하지만
  화면을 어둡게 하는 정확한 GS 설정 (대상 알파 / 별도 버퍼) 은 찾지 못했다.

## 9. 스크립트·이벤트의 라이트 켜고 끄기 [확실: 데이터 + 디스어셈블]
- **ESC 스크립트가 LGT 를 직접 켜고 끄는 경로는 없다**: 214 WAD 의 LGT 이름 (문자열·Hash127·Hash127Upper) 이 다른 리소스 (ESC·CXT …) 데이터에
  나오지 않는다 (우연 일치 6 건 제외). LGT 는 GO 그룹에도 들어 있지 않다 (최상위 GroupStart{LGT} 묶음).
- Vis 이펙터 (0x1ABAA8) 의 속성 슬롯 → 서버 타입: 0 → 0x1C·0xF (보임), 1 → 0x1E (FX), **2 → 0x27 (그림자)**, 3/4/5/6 → 0x11 (충돌 하위 0/1/3/2),
  7 → 0x1A (이미터), +0xF8 → 0x17·0x04, +0xF0 = 페이드 시간 (0x1B14E8 로 0x1C·0xF·0x27). **타입 6 (라이트) 은 없다**.
- +0xE0 (동적 세기) 를 쓰는 곳으로 찾은 것은 블레이드 라이트 램프 (0x201D18 / 0x201E24, §4) 뿐이고 [추정: 0x29CD44·라이트 함수 0x151xxx 호출자 범위에서],
  라이트 서버 넣기·빼기는 그룹 묶음 보이기/숨기기 (§8) 와 블레이드 (vt+0x30 / vt+0x40) 다. 실행 파일 문자열의 라이트 이름은
  Blades_Lights 0x1FAA10 의 "LeftBladeLight" / "RightBladeLight" 둘뿐 [확실].
- 따라서 엔진의 스크립트 쪽 연결은 Vis 슬롯 2 (그림자, §7.5) 와 슬롯 레벨 라이트 넣기·빼기 (§8) 이다.
